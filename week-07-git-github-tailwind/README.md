# Week 7 — Git, GitHub, Deployment, Testing and Tailwind Introduction

## Goal
Students learn to track changes with Git, publish a project to GitHub, deploy a static website with GitHub Pages, inspect and test a webpage, and explore Tailwind CSS briefly after learning traditional CSS.

## Learning outcomes
By the end of this week, students can:
- Explain the difference between Git and GitHub.
- Use status, add, commit, log, and basic remote commands.
- Create a GitHub repository and push a local project safely.
- Enable GitHub Pages for a static website.
- Use Chrome DevTools to inspect elements and test responsive layouts.
- Recognise Tailwind's utility-first approach and use introductory utilities.

## Weekly practical tasks
1. Initialise Git in a project folder and make at least two meaningful commits.
2. Create a GitHub repository and push the project.
3. Enable GitHub Pages for a static site.
4. Inspect the live site with Chrome DevTools and test mobile and desktop widths.
5. Build one simple card with Tailwind utilities in a classroom demo.

## Important scope and safety notes
- Git is a version-control tool; GitHub is an online hosting and collaboration service.
- Never upload passwords, access tokens, private keys, private student data, or confidential files.
- GitHub Pages hosts static files such as HTML, CSS, JavaScript, and images. It does not run a Node.js server or database.
- Tailwind is an introduction, not a replacement for CSS fundamentals. Students may use ordinary CSS in the final project.
- Follow the current official Tailwind v4 documentation. The Play CDN is for development and learning only, not production deployment.
