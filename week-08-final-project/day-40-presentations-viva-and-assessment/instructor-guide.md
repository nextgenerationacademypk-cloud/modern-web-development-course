# Instructor Guide — Day 40

## Preparation

Review the common [assessment rubric](../../assessments/assessment-rubrics.md), arrange a fair presentation order, and test classroom display and internet access. Have a backup plan if connectivity fails. Ask students to have their GitHub repository and live URL ready before their turn.

## 120-minute plan

| Time | Activity |
|---|---|
| 0–20 min | Explain presentation order, timing, assessment criteria, and submission process |
| 20–24 min | Recall required project features and submission links |
| 24–54 min | Instructor models a concise presentation and viva; explain how marks are awarded |
| 54–116 min | Student final checks and presentations |
| 116–120 min | Record feedback and next steps |

## Presentation format

Allow **up to 8 minutes per student**:
- 1 minute: website purpose and intended audience
- 2 minutes: Home, About, Services/Courses, Contact, and navigation
- 1 minute: responsive layout on mobile and desktop
- 1 minute: demonstrate the two JavaScript interactions
- 1 minute: show the GitHub repository and live URL
- 2 minutes: viva questions and one short code explanation

This 8-minute format allows up to six individual presentations in the 54–116 minute block, with a small amount of time left for transitions. If the class has more than six students, arrange an additional presentation block or a second session before Day 40; do not rush students or reduce the common assessment criteria. If the instructor uses supervised small-group demonstrations, every student must still be individually assessed and asked to explain their own work.

## Suggested viva questions

1. What is the purpose of your website and who is it for?
2. What does HTML do in your project?
3. Which CSS rule makes your layout responsive?
4. What happens when a visitor uses this JavaScript button?
5. How did you test your navigation and mobile layout?
6. What is the difference between your GitHub repository and your live website?
7. What problem did you face, and how did you solve it?

Ask each student a few questions appropriate to their project. Students do not need to memorise definitions word for word; assess whether they understand their own code.

## Evidence to record

For each student, record:
- Student name or class ID in the private instructor gradebook
- GitHub repository URL
- Live website URL or approved deployment evidence
- Whether all four sections and navigation work
- Mobile and desktop test result
- Evidence of two JavaScript interactions
- Brief notes against each final project rubric criterion
- Viva questions asked and whether the student could explain the work
- Final marks and one strength plus one improvement

Keep the gradebook private. Do not publish student marks or personal contact details in the public repository.

## Model presentation

Show the four sections, working navigation, mobile layout, two JavaScript interactions, GitHub repository, and live URL. Explain one problem solved.

## Fairness and backup plan

Use the same rubric for all students. Assess demonstrated understanding, not decorative complexity or expensive devices. If internet access fails, inspect saved local evidence and the repository commit history where available, record the issue, and arrange a fair retry for live deployment. Never request passwords, tokens, or verification codes.
