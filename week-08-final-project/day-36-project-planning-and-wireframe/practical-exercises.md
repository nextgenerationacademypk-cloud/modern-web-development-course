# Practical Exercises — Day 36: Final Project Planning and Wireframe

## Goal

Choose a realistic website topic, identify its audience, plan the four required sections, sketch a wireframe, and prepare the starter folder.

## Required practical

### Task 1

Write a one-sentence purpose and identify the intended audience.

**Check:** Show the result to your instructor before moving on.

### Task 2

Plan a Home section with a heading, short introduction, and call to action.

**Check:** Show the result to your instructor before moving on.

### Task 3

Plan About, Services/Courses, and Contact content using short bullet points.

**Check:** Show the result to your instructor before moving on.

### Task 4

Draw a simple wireframe showing header, navigation, main sections, and footer.

**Check:** Show the result to your instructor before moving on.

### Task 5

Choose two interactions already practised, such as mobile navigation and FAQ show/hide.

**Check:** Show the result to your instructor before moving on.

### Task 6

Copy the instructor starter folder and open the folder in VS Code.

**Check:** Show the result to your instructor before moving on.

## Required completion checklist

- [ ] Choose a suitable topic and audience.
- [ ] Describe the purpose of Home, About, Services or Courses, and Contact sections.
- [ ] Sketch a readable desktop and mobile page layout.
- [ ] Select two familiar JavaScript interactions.
- [ ] Create and inspect the supplied starter project folder.

## Troubleshooting

1. Read the exact browser or terminal message before changing code.
2. Check file names, folder location, spelling, and letter case.
3. Save the file and refresh the browser preview.
4. Test one change at a time.
5. Ask the instructor to review the smallest failing example if you are stuck.

## Optional challenge

Improve one small detail only after the required tasks are complete. Be ready to explain what you changed and why.

## Expected result

Your own project should show visible progress toward the final website. You should be able to explain the work rather than simply show copied code.
