# Instructor Quality Checklist

Use this checklist before delivering a lesson or publishing it in the student repository.

## Curriculum and level
- [ ] The lesson matches the approved 40-session schedule.
- [ ] Prerequisites were taught in an earlier session.
- [ ] Learning outcomes describe skills students can demonstrate.
- [ ] The amount of new material is suitable for absolute beginners.
- [ ] Optional challenges are separated from required work.

## Technical accuracy
- [ ] Explanations use correct current terminology.
- [ ] Code examples are complete and syntactically correct.
- [ ] File names, folder paths, and links match the instructions.
- [ ] Every example has been run and checked.
- [ ] Any required extension, package, or tool is explained.
- [ ] External documentation links are official or reliable.
- [ ] Version-specific instructions identify the version or are checked against current official documentation.

## Teaching quality
- [ ] Lecture notes use simple English.
- [ ] The instructor guide includes preparation and a 120-minute plan.
- [ ] The demonstration is broken into understandable steps.
- [ ] Questions and understanding checkpoints are included.
- [ ] Common beginner mistakes and troubleshooting steps are included.
- [ ] Student practical work receives most of the lesson time.

## Practical learning
- [ ] A guided exercise is provided.
- [ ] A required independent task is achievable.
- [ ] An optional extension is available for faster students.
- [ ] The expected result is clear.
- [ ] Homework reinforces the lesson without introducing unlearnt topics.
- [ ] The quiz checks the stated learning outcomes.

## Visuals and accessibility
- [ ] Every visual supports a specific learning point.
- [ ] Diagrams are readable and correctly labelled.
- [ ] Software screenshots are genuine and current.
- [ ] Images have useful alternative text or captions.
- [ ] Examples use semantic HTML and meaningful labels where relevant.
- [ ] Colour is not the only way information is communicated.

## Assessment and student safety
- [ ] Marking criteria are visible before the task.
- [ ] Students can explain the code they submit.
- [ ] Examples do not ask students to publish passwords or personal contact details.
- [ ] No private answer key or unreleased exam solution is in the public repository.

## Final decision

A lesson should be marked **Ready** only when all essential checks pass. If a check fails, fix it or clearly record the limitation before classroom use.
