# Assessment Rubrics

Use these rubrics consistently. Explain the task and criteria before students begin. Give partial marks for correct progress and useful evidence of understanding.

## 1. Weekly practical work — 30 marks

The instructor collects practical work across the eight weeks. The exact weekly distribution is in the [Assessment Policy](../course-outline/assessment-policy.md). Use the following common criteria to award the 30 course-wide marks.

| Criterion | Marks | Full-credit standard |
|---|---:|---|
| Required features | 10 | All stated core requirements are present and work |
| Correctness and testing | 7 | Student tests the result and fixes obvious errors |
| Code structure and organisation | 5 | Files, names, indentation, and code structure are understandable |
| Usability and accessibility habits | 4 | Content is readable; links, labels, image text, and layout are appropriate for the task |
| Explanation and ownership | 4 | Student can explain the main parts and make a small requested change |
| **Total** | **30** | |

For each criterion, award full marks when the standard is met, around half when partially met, and zero only when there is no relevant evidence. Adapt the examples to the week's technology without changing the total.

## 2. Homework — 15 marks

| Criterion | Marks |
|---|---:|
| Task requirements completed | 7 |
| Code runs and has been checked | 4 |
| Files are organised and readable | 2 |
| Student can explain the work | 2 |
| **Total** | **15** |

Homework should practise material already taught. Do not penalise a student for not using an advanced technique that has not been taught. The weekly mark allocation is listed in the Assessment Policy.

## 3. Mid-course practical exam — 15 marks

**Timing:** End of Week 4.  
**Suggested duration:** 60–75 minutes, adjusted to the class pace.

Create a simple responsive information page for a fictional club, academy, or service.

| Area | Marks |
|---|---:|
| HTML structure and content | 4 |
| External CSS connection and styling | 4 |
| Layout and spacing | 3 |
| Responsive behaviour | 3 |
| Student explanation | 1 |
| **Total** | **15** |

**Pass requirement:** at least 9 out of 15 marks (60%). If a student does not pass, provide feedback and one supervised re-assessment opportunity where practical.

## 4. Final project — 30 marks

A **single-page website** with Home, About, Services or Courses, and Contact sections can receive full marks. Separate HTML pages are optional and do not earn extra required marks.

| Area | Marks |
|---|---:|
| HTML structure and content | 5 |
| CSS styling and layout | 5 |
| Responsive behaviour | 5 |
| JavaScript features | 5 |
| Navigation, usability, and accessibility | 3 |
| GitHub repository and live deployment | 4 |
| Presentation and explanation | 3 |
| **Total** | **30** |

For the 3 marks for navigation, usability, and accessibility, look for:
- Navigation links reach the correct sections and can be used with a keyboard.
- Text has readable contrast and is easy to read at mobile and desktop sizes.
- Informative images have meaningful alternative text.
- Form controls, if used, have clear labels; interactive actions use appropriate buttons.

Do not require a working back-end contact form. The supplied form is a browser demonstration only and does not send or store messages.

### Final project performance guide

- **Full marks:** requirement works, is appropriate, and the student can explain it.
- **About half marks:** requirement is partly complete or has a minor issue.
- **Low marks:** major parts are missing or do not work.
- **Zero:** no relevant work is submitted for that criterion.

A project should be evaluated on the student's demonstrated skills, not on visual complexity or the number of pages alone.

## 5. Theory and viva — 10 marks

Use short questions across the course. Ask students to explain terms, read a small code sample, or describe how they solved a problem.

| Area | Marks |
|---|---:|
| Web and HTML concepts | 2 |
| CSS and responsive design | 2 |
| JavaScript and DOM concepts | 3 |
| Git, GitHub, and deployment concepts | 2 |
| Clear explanation of own work | 1 |
| **Total** | **10** |

## Completion rules

A student must:
- Attend at least 32 of 40 sessions.
- Submit the required weekly practical assignments and final project.
- Pass the mid-course practical exam with at least 9/15.
- Present the final project.
- Earn at least 60/100 overall.

Record attendance, assessment marks, and any approved catch-up or re-assessment separately.
